# Support

## Where to ask

- **Bug reports and reproducible build failures:** open a GitHub issue in the ARES repository.
- **Feature proposals:** describe the problem, intended behavior, constraints, and alternatives in an issue before submitting a large change.
- **Security vulnerabilities:** follow [SECURITY.md](SECURITY.md); do not report exploitable details publicly.

## Include useful diagnostic information

When reporting a problem, include:

- operating system and version;
- relevant component and commit SHA;
- exact command or action performed;
- expected result and actual result;
- sanitized error output and relevant logs;
- whether the issue reproduces consistently.

Remove passwords, access tokens, MQTT credentials, private keys, device identifiers that should remain private, and personal data before posting logs.

## Hardware and safety

Clearly distinguish simulated, desktop-only, bench, and flight tests. Include the exact board revision, wiring, supply voltage, and peripheral versions when relevant. Do not perform flight tests based solely on a successful software build or issue discussion.

ARES is a prototype. It is not a substitute for certified rescue, aviation, or emergency-response equipment.
